# 蓝拍战神好帅帅 · 专门打扰晴空萬李

一个四通道休闲塔防小游戏。四条路上种卷梨攒梨光，放站神挥拍挡易帝，撑过八波就算守住。
基调是解压，不是硬核：波次间隔宽松、前期压力低，输了也有温柔的文案。

- 技术栈：Vue 3 + Vite + TypeScript + Canvas 2D + Pinia
- 双端复用：H5 网页（在线链接直接玩）+ 后续 Tauri 打包成 Windows 离线 exe
- 全部工程文件、依赖、缓存、构建产物都在 **D 盘**，项目自身不读写 C 盘
- 横屏游玩：PC 直接横屏铺开；手机竖着打开会提示横过来，转屏自动消失，不想转也能点「就在竖屏玩」直接进

## 怎么玩

四条横向通道，**一条通道就是一行格子**：这一行既是放置位，也是敌人的行进道，
所以卷梨和站神是直接种在敌人要走的那条路上的。敌人从左边入口进场，一路向右走到终点门。

1. 点建造栏里的 **卷梨**，点通道上的空格种下，它会周期产 **梨光**
2. 攒够 75 梨光放 **站神**，它只会朝**自己那条通道**里最靠前的敌人挥手打出一支球拍（单体命中，不穿透）
3. 四条路都要有人守，漏一只扣 1 点守护
4. 点已放的单位可以看详情；卷梨还能花 90 梨光**强化**，立刻释放「晴空万里」拿一大笔梨光，并弹出彩蛋
5. 放错了点 **铲子**，再点那个单位，确认后收回，**返还一半梨光**（卷梨退 25，站神退 37）

| 单位 | 造价 | 作用 |
| --- | --- | --- |
| 卷梨 | 50 | 每 5.5 秒产 25 梨光；强化后每 4 秒产 45，并一次性 +150 |
| 站神 | 75 | 每 1.15 秒挥拍打出一支球拍，伤害 22，射程 3.6 格，只打本通道，单体不穿透 |
| 易帝 | — | 敌方单位，出生时随机选一条通道，之后直行到底 |

规则要点：
- 梨光**只由卷梨产出**，击杀敌人不给梨光
- 站神**只能打同一条通道**的敌人（当前版本锁定，跨通道留给后续版本）
- 敌人选定通道后不会换道、不会绕路；有敌人正踩着的格子不能放单位
- 生命归零即失败，打完 8 波即通关

快捷键：`空格` 暂停/继续；`Esc` 先关掉二次确认弹窗，再退掉当前选择；右键取消选择。

### 手机上怎么打开

横着看最舒服，竖着也能进：

- 竖屏打开时会弹一层「横过来玩更舒服」，点 **全屏横屏** 自动转，或者**把手机转成横的**，提示会自己消失
- 不想转就点 **就在竖屏玩** —— 立刻进游戏，本次会话不再弹（竖屏下棋盘会缩到整屏宽，能玩但字小）
- 在微信 / App 内置浏览器里，`requestFullscreen` 和 `screen.orientation.lock` 常常不可用，
  这时「全屏横屏」不生效，提示会改成「把手机转成横的就行」，「就在竖屏玩」永远可以点
- 电脑上（非触屏）不会弹这个提示

## 素材替换教程

**所有美术素材都放在 `public/assets/` 下，按固定文件名覆盖即可，代码不用动一行。**

### 角色图

| 文件名 | 对应单位 | 当前素材 |
| --- | --- | --- |
| `public/assets/units/pear.png` | 卷梨 | 320 × 320 透明 PNG |
| `public/assets/units/guardian.png` | 站神 | 320 × 320 透明 PNG |
| `public/assets/units/yidi.png` | 易帝 | 320 × 320 透明 PNG |

要求：背景透明、主体居中、裁到内容边界（不要留大片空白）。单位会按格子的 88%、敌人按 82%
等比缩放绘制，主体占画布 85% 左右最合适。

> 单位和敌人现在站在同一行里，纵向各有 3 / 5 像素的小偏移避免完全重合，
> 走位交叠时敌人带一层淡白描光把剪影托出来。想调这个错位改 `map.ts` 里的
> `unitOffsetY` / `enemyOffsetY`，正负不要超过 8，否则贴边那一行会被画布切到。

### 子弹

| 文件名 | 用途 | 当前素材 |
| --- | --- | --- |
| `public/assets/bullet/paddle.png` | 站神打出去的球拍 | 200 × 200 透明 PNG |

站神的攻击表现是「挥手打拍子」：开火时手上出现球拍沿弧线扫过，随后球拍飞出成为子弹并旋转。
这一张图同时用于**手上的拍子**和**飞行的子弹**，拍面要完整，四周别留太多透明边。

### 背景

| 文件名 | 用途 | 当前素材 |
| --- | --- | --- |
| `public/assets/bg/bg.png` | 棋盘底图 | 800 × 640 |

棋盘是 **10 列 × 4 行、每格 72 像素（720 × 288，比例 2.5:1）**。底图会等比铺满并居中裁切，
不会拉伸，所以什么比例都能用，但 5:2 左右最不容易裁掉重点。

底图只以 55% 不透明度叠在下面当质感，上面盖的是四条深浅交替的草地通道 —— 通道必须一眼分得清，
底图太抢戏反而会让人觉得有八条路。

### 音频

`public/assets/audio/` 下可放：`bgm.mp3`（循环）、`shoot.wav`、`build.wav`、`pear.wav`、
`upgrade.wav`、`remove.wav`、`hit.wav`、`win.wav`、`lose.wav`。

**全部可选。** 文件不存在时游戏会用 Web Audio 实时合成替代音（BGM 是一段很慢的五声音阶分解和弦），
不会报错也不会静音卡死。放进文件就自动优先播放。

> 关于「饿啊」：这是网络音效梗，我没有内置任何音频素材，也无法生成真人声音。
> 把对应的音频文件命名成 `hit.wav` 放进 `audio/` 目录，受击时就会播它。

### 缺图会怎样

任何一张图缺失或加载失败，都会自动退化成程序化绘制的占位图形（绿梨、蓝帽小哨兵、橙团子、蓝光点），
游戏照常运行。所以可以边玩边补素材，不用等美术齐了才开始。

### 这批素材是怎么处理进来的

原始图是豆包生成的方形插画，背景是烘焙进去的浅绿棋盘格（不是真透明），所以做了三步处理才放进项目：

1. **抠背景**：从四边泛洪，用「绿色偏差 ÷ 亮度」的比值判定背景（背景稳定在 0.15 以上，
   被环境染绿的白色衣物只有 0.05），并顺带吃掉底部的软投影；阴影交给 Canvas 另画，比抠图更干净。
2. **裁边补方**：按 alpha 裁到内容边界，再补成正方形，保证角色在格子里不会偏心。
3. **缩放**：角色输出 320×320、子弹 200×200，兼顾清晰度和体积；背景另外做了柔化。

背景图底部自带的「豆包AI生成」字样是直接裁掉的（不是涂抹），所以现在看到的是纯画面。

## 文案彩蛋怎么改

所有会出现在界面上的文字都在 `src/config/copywriting.ts`，改字不用碰逻辑：

- `SKILL_EASTER_EGGS`：强化卷梨时随机弹一条，想加就往下追加，删到只剩一条也行
- `RESULT_COPY`：通关 / 失败的标题、三行正文、按钮文字
- `INTRO_HINT`：棋盘下面那句引导
- `TOAST_COPY`：梨光不足、位置被占、铲子收回之类的提示
- `SHOVEL_COPY`：铲子二次确认的标题和正文（`{name}` / `{refund}` 会被替换）
- `FOOTER_COPY`：页脚署名

## 数值怎么调

| 想改什么 | 改哪个文件 |
| --- | --- |
| 初始梨光、生命、波次间隔、铲子返还比例 | `src/config/economy.ts` |
| 单位造价、产量、伤害、射程 | `src/config/units.ts` |
| 敌人血量、速度、扣血 | `src/config/enemies.ts` |
| 每波敌人数量与节奏 | `src/config/waves.ts` |
| 通道条数、列数、格子大小、单位错位 | `src/config/map.ts` |

`map.ts` 里 `rows` 等于 `lanes`：一条通道一行。想加第五条路就同时把这两个数改成 5，
棋盘高度会自动变，渲染和判定都跟着走。改完记得清一下浏览器缓存刷新。

## 加新单位

不需要动战斗代码，三步：

1. `src/types/game.ts` 的 `UnitType` 里加一个标识
2. `src/config/units.ts` 的 `UNITS` 里追加配置：产资源用 `role: 'producer'`，攻击用 `role: 'attacker'`
3. 把透明 PNG 丢进 `public/assets/units/`，文件名对上 `sprite` 字段

建造栏、放置、强化、详情条、渲染会自动识别。

## 构建与部署

```bash
npm run build      # 产物在 dist/，纯静态，丢任何静态服务器都能跑
npm run preview    # 本地起个预览服务
npm run serve      # 线上入口：先 vite build，再读 PORT 托管 dist
```

`vite.config.ts` 里 `base: './'`，所以 `dist` 可以放在任意子路径下，不要求部署在域名根目录。

> **`npm run serve` 为什么要自己构建？**
> 发布平台上传源码时会排除 `dist`（构建产物），沙箱里保留的是上一次部署留下的旧 `dist`。
> 如果启动时直接 `vite preview`，线上跑的就还是上一版 —— 改完代码发布却发现页面没变，就是踩了这个坑。
> 所以 `scripts/serve.mjs` 现在是「先 `vite build`，构建成功再起 preview」，保证线上产物永远对应最新源码。

## 技术说明

- 逻辑层是纯 TypeScript，`GameEngine` 只对外暴露 `update(dt)`、几个操作指令和两个快照方法，
  完全不感知 Vue、Canvas 和未来的 Tauri
- `GameLoop` 固定 1/60 秒步长，120Hz 和 60Hz 屏幕跑出来的结果一致
- **单层网格**：`MAP_CONFIG.rows === lanes`，一条通道一行，行号就是通道序号，
  所以「单位在不在本通道」直接比行号，不需要换算
- 站神索敌用**水平距离**判定，和界面上画的「同通道射程带」完全一致 ——
  以前用圆形距离 + 裁剪，看着能打到、实际算不到的情况现在没有了
- 铲子收回时单位立刻从逻辑层移除，同时留一张 0.5 秒的淡出残影（`engine.ghosts`），
  不会打断正在飞的子弹，也不会让单位在动画期间继续产出
- Pinia 里用 `markRaw` 存引擎实例，防止深度代理破坏内部对象
- 横屏适配：棋盘宽度按 `calc((100dvh - 常量) * 2.5)` 反算，保证一屏内放得下、不出现滚动

## 更新日志

### 2026-11-15 · 修掉「竖屏提示把人挡在门外」

- **问题**：手机竖屏打开分享链接时，「横过来玩更舒服」是整屏硬遮挡，唯一的出口是「全屏横屏」按钮；
  在 App 内置浏览器 / 微信 WebView 里全屏和转屏都不可用，按钮点了没反应，玩家就彻底进不去游戏
- 加**「就在竖屏玩」**出口：点了立刻进游戏，`sessionStorage` 记住本次会话不再弹
- 转成横屏**自动消失**：判定改成直接比 `innerWidth` / `innerHeight`，不再依赖
  `(orientation: portrait)` 的 `change` 事件（微信、iOS 旧版 WebView 上那个事件经常不触发），
  同时监听 `resize` / `orientationchange` / `visualViewport` / `fullscreenchange`，iOS 尺寸变化偏晚就补几次延时重测
- 按钮失败时给出准确文案「这台设备不支持自动转屏，把手机转成横的就行」，不再让玩家对着没反应的按钮反复点
- 非触屏设备（电脑上把窗口拉成竖的）**永远不弹**，避免桌面被锁死
- 竖屏宽度 ≥ 620px（平板竖屏）不弹，棋盘本来就放得下
- 去掉 `index.html` 里的 `screen-orientation` / `x5-orientation = landscape`：这种整页强制横屏的老方案
  在部分 WebView 里会把页面信箱化、点击坐标错位，和新的竖屏兜底冲突
- 补 `viewport-fit=cover` + 安全区 padding，横屏刘海屏不再压到两侧内容；窄屏顶栏保留「全屏」按钮
